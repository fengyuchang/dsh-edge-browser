# 0.4.2-dsh.7：后台零视口恢复

后续复验通过页面内 `innerWidth/innerHeight` 确认了后台任务页的真实 `0×0`，这会同时破坏元素引用、几何定位和截图。dsh.6 的调整窗口预检又要求先读到正数视口，导致恢复入口被同一问题挡住。dsh.7 修复这两个路径；保留 dsh.6 的读取时限、取消、迟到回执保护和全部会话归属检查。

## 恢复行为

同步和普通页面读取共用视口检查。仅当目标是本会话 Agent Window 中已授权的任务标签、且真实读取为零尺寸时，才以中性的桌面渲染尺寸 `1280×800` 恢复该标签；正常尺寸直接沿用。所有读取与配置均有时限，并在等待后复查会话、调试连接、取消和人工控制状态。尺寸不可测量或恢复失败时，返回完整的 `Task viewport is not ready` 与“不曾发送页面输入”说明，不把它解释成目标不存在，不自动重放动作。

这里恢复的是页面的渲染尺寸，不是把 OS 窗口恢复到前台。生产代码采用现有 CDP `Emulation.setDeviceMetricsOverride`，设置 `mobile:false`、`deviceScaleFactor:0`；不使用已弃用的 `setVisibleSize` 作为恢复方法。自动恢复有独立归属，释放后台控制、调试连接或恢复查看任务窗口时，只清理本插件的自动配置，后续显式手机/设备模拟继续保留。Chrome 的窗口 API 不允许在一次调用中同时设置 `minimized` 与宽高，因此没有使用“先显示、再最小化”的规避方式。[窗口 API](https://developer.chrome.com/docs/extensions/reference/api/windows) · [CDP 定义](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Emulation.pdl)。

调整窗口仍验证实际外框和实际视口。零视口可进入恢复流程；外框改变后，若最小化渲染器没有跟随尺寸，则按目标尺寸恢复并重新读取确认。无法读取和真正的零尺寸继续区分；发送更新后的失败仍标明效果可能已经发生，不能据此盲目重试。

旧版会在任务窗口创建蓝色“DeepSeek Harness”标签组，但记录仅在内存中，重启后无法按原记录收尾。新版停止自动创建或扩展任务分组，任务归属仍由会话和控制条表达。启动时仅解除旧版准确名称及蓝色样式的标签组；保留全部网页、其他名称/颜色的分组，不以这些残留标签推断控制权或复用资格。

## 验收

3,729 项扩展测试通过（425 跳过），721 项原生插件测试通过（10 跳过），两端类型检查通过。[公开验证数据](validation-0.4.2-dsh.7.json)。

独立 headless Edge 未传任何启动窗口尺寸，以 `noFocus:true` 建立最小化任务页。测试通过 CDP 在真实渲染器上设为 `0×0`，并用页面内 `innerWidth/innerHeight` 确认；随后同步恢复到 `1280×800`，观察取得引用、截图生成有效 PNG，标签填写和角色点击在实际页面各执行一次。再次归零后，普通读取和 `640×480` 调整窗口都可恢复，整个后台部分没有恢复或激活窗口。完整不可测量说明能够经 CLI 传回原生插件。

该组共 12 项通过，还包括：真实扩展 worker 重启后，仅解除旧版蓝色标签组的 2 个标签，4 个网页全部保留、2 个无关分组保留；新建任务标签不再分组；释放后台控制只清理自动尺寸，后续显式 `390×844` 手机模拟仍保留。

另有 8 项纯后台读取/跳转回归通过：8 次普通或提前跨站跳转后均能重新同步；取消等待中的无障碍读取及时返回、迟到回执不补发点击，原 Chrome 命令结束后继续原会话。旧命令仍等待时，新捕获明确拒绝，不能把缓存同步或刷新当作绕过方法。

既有 22 项协作、人工接手、批量取消、空闲窗口复用、保留表单与任务收尾检查通过；标注路由与接收端由独立的项目检查验证。这组使用固定启动尺寸，并在独立 headless 进程内恢复窗口以模拟人工操作；不称为全程最小化验收。8 次点击截图采样 `368` 帧，控制条和光晕隐藏/移除均为 0。三组共 `182` 次桌面采样，未检测到测试进程显示在用户桌面或取得前台焦点。

**适用范围：** 零视口是对真实渲染器的人工归零，不等于自然复现日常 Edge 配置；日常现象以原复验报告为依据。未指定尺寸的原生 Windows Edge 在非活动桌面上未成功开放 CDP，本轮不声称该起窗路径通过。headless 恢复窗口状态不发原生尺寸事件，这条事件路径由归属单元测试覆盖；共享控制清理及显式设备模拟保留已在真实隔离浏览器验证。日常已加载代码仍需单独核对，发布和磁盘文件不代表运行版本。

## 对 dsh.6 验收的更正

dsh.6 两组后台测试实际都带有 `--window-size=1280,900`，生成测试脚本时遗漏了移除参数。原文“原生 Windows 路径未指定启动尺寸”不准确，[历史说明](recovery-0.4.2-dsh.6.md)及[验证 JSON](validation-0.4.2-dsh.6.json)已更正。旧记录中的通过结果仍对应原始测试条件；它不能证明未指定启动尺寸也正常，替换几何回执也不能证明真实渲染器已归零。

复验时原生插件已运行 dsh.6，Edge 扩展仍运行 dsh.5。因此不能用当轮旧扩展的文案断定 dsh.6 的完整版提示被上层截断。dsh.7 对不可测量尺寸另做端到端回执检查。磁盘版本、宿主 PID 和运行版本须分别核对；同一 Harness 进程可以热重载插件，Edge 已加载的后台脚本则不会因磁盘文件更新自动替换。
