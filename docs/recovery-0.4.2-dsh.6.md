# 0.4.2-dsh.6：后台读取、取消与验收补充

这轮根据 dsh.5 更新验证报告，检查隐藏页面定位、跳转后同步、操作取消和视口诊断。源码、CLI 与协议继续基于 BrowserSkill 0.4.2 / 1.8；不修改 Harness 内核、其他插件或登录设置。

## 已定位并修复

角色与标签定位原先调用 `Accessibility.queryAXTree`。独立最小化浏览器中，CSS 填写与跳转正常，该查询却可一直等待页面渲染生命周期更新，即便提前启用无障碍域也会发生。dsh.6 改用已有读取时限的 `Accessibility.getFullAXTree`，准确筛选角色和名称，再沿用原生目标检查。查询完成后只清理原来的调试连接；控件歧义、不可操作、归属或上下文变化仍拒绝输入。

另一个问题是取消信号原先只在发送前检查，未传到已经等待的安全读取。dsh.6 让这些读取及时结束调用等待，并补齐 DOM 节点与几何查询时限。Chrome 命令实际结束前仍阻止后续读取；迟到回执只释放旧闸门，不恢复已取消操作，不自动重放点击。原生输入、按键释放、上传和下载保持原有取消清理，刷新也继续遵守操作归属与输入保护。CLI 的通用提示可能仍建议刷新，应以具体回执中的“原读取仍在 Chrome 中等待”为准，该提示不表示可以绕过闸门。

跳转后“动作已经执行、但上下文已变化”仍可能返回结果不确定；这时应检查实际页面并同步，而不是再点一次。已发出的浏览器命令真正失去响应时，不承诺可以无条件刷新绕过它；可以结束自己的任务并另建页面，其他会话不受影响。

## 视口与错误含义

- `ref_not_found`：该引用未在当前观察中取得、已失效或属于其他标签，不能据此推断网页没有该元素。重新观察并使用实际返回的引用；截断时增加观察预算。
- `selector_not_found`：当前精确语义名称没有可见匹配，检查页面和名称。
- `viewport unavailable`：视口或几何数据不可用。`@view 0x0` 可能来自未就绪/最小化的渲染器，也可能是捕获读失败，不能直接当作页面为空。同步恢复后再选择动作，不自动把浏览器切到前台。

报告中的日常 Edge `0×0` 现象尚不能仅凭报告确定为实际窗口尺寸归零。独立原生 Windows 最小化窗口与 headless 路径需分别检查，下面列出实际验证范围；不通过强制弹出窗口掩盖问题。

## 实测记录

3,723 项扩展测试通过（425 跳过），721 项原生插件测试通过（10 跳过）；两端类型检查通过。既有 22 项协作/标注/会话隔离/收尾验收通过，另在两种环境各通过 8 项后台回归。[可公开的验证数据](validation-0.4.2-dsh.6.json)。

| 环境 | 初始状态 | 视口 | 后台回归 |
| --- | --- | --- | --- |
| 独立 headless Edge | minimized，未恢复或激活 | 1250×798 | 8 项通过，8 次跨站跳转后可同步 |
| 原生 Windows Edge，独立非活动桌面 | minimized，未给启动尺寸，未恢复或激活 | 1258×809 | 8 项通过，8 次跨站跳转后可同步 |

两种路径均验证：观察后后台 role/label 定位、未知 ref 与不存在目标区分、取消正在等待的无障碍读取、迟到回执不补发输入、原读取结束后继续原会话、注入不可用几何后的提示与恢复、活动版本一致。取消期间未变化的缓存同步可以成功；新快照读取在 Chrome 旧命令未结束时明确拒绝，不冒充会话永久收尾。

桌面与前台归属共 116 次采样，未见测试进程在用户桌面显示窗口或取得前台焦点。控制条/光晕回归的 8 次点击截图共采样 431 帧，隐藏及组件移除均为 0。测试使用独立配置、独立后台服务、合成聊天和本地页面，不读取日常登录，也不向真实聊天发送测试消息。

**仍需日常环境复验：** 未自然复现报告中的持久 0×0；本轮实际覆盖了最小化后台窗口，以及人为注入不可测量几何后恢复读取。前者不替代日常 Edge 配置和其他扩展组合的验证，后者也不等于证明所有窗口尺寸问题都已修复。

## 加载验证

更新文件不会自动替换已经加载的代码。Edge 需要重新加载扩展；Harness 需要单独重载 BrowserSkill，无法单独重载时等其他任务结束再正常重开 Harness。无需重装或改端口。

优先检查运行中的 `/bsk-observation/state` 的 `pluginVersion`，并让原聊天重新读取 `/browser-skill` 后调用 diagnose。旧枚举不含 diagnose/batch 表示运行工具或该聊天所见 schema 尚未更新。宿主进程启动时间不能单独证明插件没有热重载；同一个进程也可加载新的插件版本。无活动浏览器任务时，状态里的 `available:false` 不能单独作为版本失败的证据。
