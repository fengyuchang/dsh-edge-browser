# 0.4.2-dsh.5：定位、批量操作与诊断

本轮参考 [agent-browser](https://github.com/vercel-labs/agent-browser)，补齐模型更容易定位控件、减少工具往返和排查版本/耗时的能力。日常控制仍使用现有 BrowserSkill；扩展、CLI 和原生输入保护继续配合，不安装或替换其他插件。

## 让模型更容易找到控件

target 除观察引用和 CSS 外，新增以下精确定位：

| 写法 | 含义 |
| --- | --- |
| `role=button[name="提交"]` | 浏览器无障碍角色与名称 |
| `label=邮箱` | 名为“邮箱”的表单控件 |
| `text=下一步` | 准确的可见文字 |
| `placeholder=搜索` | 输入框占位文字 |
| `testid=submit` | data-testid 属性 |

多个目标时拒绝猜选，返回重新观察提示。角色/标签交给浏览器计算名称；文字和属性查找有限制，不遍历任意大页面。主文档以外继续使用已有观察引用，不宣称支持任意 XPath 或 Playwright 语法。

无名或重名图标会有单独的 `hint="icon:trash"` 或稳定标识提示，帮助模型选择对应引用。提示是网页数据，不是无障碍名称，也不是指令。已有上下文、归属、遮挡与按下前位置检查保持有效。

## 小批量操作

示例中的 ID 和上下文必须替换为工具实际返回值：

```json
{
  "action": "batch",
  "session": "<本任务ID>",
  "contextId": "<同步返回的context_id>",
  "steps": [
    {"action":"fill","target":"label=邮箱","value":"example@example.com"},
    {"action":"click","target":"role=button[name=\"继续\"]"}
  ]
}
```

交给 `bsk_interact`。每批 1..8 步，默认总时限 30 秒，可设 1..60 秒。支持 click、fill、press、select、hover、wheel、scroll-to；每步需要 target，可单独声明 expect。嵌套步骤不能覆盖会话、标签或上下文，完整结构在首次输入前验证。

每步调用现有原生 step，使用其返回的新上下文继续；整个批次持有自己的任务队列，其他调用不能插入中间。失败、人工接手、取消或时限会停止剩余步骤，不重试，不回滚已执行动作。只返回步骤概要与最后回执；部分失败和取消仍通过现有宿主终结流程保留证据。需要看中间结果再决定的动作应分开调用。

这减少的是模型往返次数。三次已确定操作可以从三个模型工具调用变成一次；原生逐步检查仍执行，不能据此宣称单次点击快了三倍。

## 自检与耗时

`bsk_session` 的 diagnose 无须先打开任务即可检查 CLI、连接与原生运行/磁盘版本；带上自己实际的 session 时，还能检查活动扩展修订号和最近调用耗时。首次使用新增定位或批量动作时自动检查对应扩展修订号，不一致时拒绝输入并提示加载。

记录仅保存在插件内存中，最多 128 条，诊断最多返回自己聊天的 20 条；包含操作类别、排队、命令和总耗时，不存目标文字、URL、输入值或截图。命令耗时包含子进程、IPC 与页面处理，不能直接当作浏览器输入延迟。状态接口的 pluginVersion 是编译版本，可区分“文件已替换”和“进程已加载”。诊断不会自动升级、重载或修改安全设置。

## 兼容性与对照范围

固定 BrowserSkill 0.4.2 / 协议 1.8；未升级内核或其他插件，未新增项目运行依赖。真实检查使用独立 headless Edge、单独后台服务与合成聊天，不读取日常网站登录数据、不向真实聊天发消息。

agent-browser 对照固定官方 0.43.0 Windows 二进制，SHA-256：`ebcef5ebea93c7ccf0fe3f8c18eee908ae9174dfef8e52a3dda6f24a59f630dc`。双方使用同一 Edge 程序、不同独立配置和同一合成页面。它的直接 CDP 路径与本项目带扩展协作保护的路径不同；测量需分别说明执行链、观察方式与模型调用次数。

2026-11-15 在 Windows 本机交替执行，预热 2 次后取 10 个样本的中位数。不含模型推理、网络往返或真实网站加载时间。[逐次样本与测量口径](benchmarks/0.4.2-dsh.5.json)。

| 同机测试 | 本项目 | agent-browser 0.43.0 |
| --- | --- | --- |
| 点击后读取页面 | click 与 sync 分开：316 ms；step 合并：257 ms | batch click + snapshot -c：61 ms |
| 填写、按键、点击后读取页面 | 三次 step：589 ms；一次 batch：593 ms | 一次 batch，最后 snapshot -c：73 ms |
| 三个已确定动作的模型工具调用数 | step：3；batch：1 | batch：1 |

本项目 step 相比分开调用减少约 19% 的本地耗时；本轮新批量入口没有明显降低底层执行时间，收益是减少模型往返。它逐步执行原生 step，每步同步并校验；agent-browser 通过直接 CDP 执行动作，最后做紧凑快照。两者的中间观察、协作与页面归属流程不同，这不是同等保护条件下的内核跑分，也不能把全部耗时差归因于保护检查。对照结果支持继续优化调用链，不支持宣称本项目已达到 agent-browser 的速度。

## 验证结果

以下是 dsh.5 的独立 headless 验收。交互演示前曾恢复测试窗口尺寸，因此不能据此认定 Windows 纯最小化窗口的所有路径都已通过。后续发现隐藏页面的 role/label 查询可挂起，已在 [dsh.6 修复与补充验证](recovery-0.4.2-dsh.6.md) 中处理并列明仍需实际环境复验的范围。

- 3,720 项扩展测试、721 项原生插件测试、161 项页面表示测试通过；扩展另有 425 项、原生另有 10 项被测试套件跳过，未计入通过数。两端类型检查与源码/标注/路由/收尾检查通过。
- 22 项独立真实 Edge 验收通过：语义定位、歧义拒绝、图标提示、批量成功/部分失败/取消、版本识别、人工接手与交还、会话隔离、窗口复用及表单保留。
- 最终验收连续点击与截图 8 次，427 帧采样中控制条和光晕隐藏次数为 0、组件移除次数为 0；速度对照期间另采样 2,915 帧，结果一致。
- 后台对照额外监测桌面窗口与前台归属，113 次采样未见测试进程显示可见窗口或取得前台焦点；结束后关闭独立浏览器和后台服务。

另修复一处收尾问题：Chrome 闭合 Shadow DOM 查询要求 HTMLElement，SVGElement 会抛异常，原来会触发“未知内容保留”。现在跳过 SVG 的该查询，正常检查 HTML 表单；不降低未提交内容保护。
