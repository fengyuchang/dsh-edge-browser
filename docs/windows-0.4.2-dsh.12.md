# 0.4.2-dsh.12：保留页面时不再增加窗口

## 原因与修复

此前的空闲窗口池能够复用旧窗口，但明确保留结果时又创建一个新的结果窗口，再把页面移过去。即便任务已经结束，这条路径仍可随保留次数累积窗口。不能把 Edge 的多进程数量当成窗口数量；本次定位的是实际窗口生命周期。

新版直接在原任务窗口保留必要页面，不增加结果窗口或占位页，不移动标签、不改变窗口焦点或显示状态。保留页马上退出 AI 输入授权，保留标记仍保护后续清理，即使解除调试连接失败也可以重试。结束后该窗口只有在没有活动任务且未被用户聚焦时，才进入插件已有的空闲复用流程。旧结果不会因为复用而成为新任务的输入或关闭目标。

普通页和临时任务仍经原生收尾关闭；借入的用户页仍归还原位置。表单、人工操作和无法确认的内容继续保留。关闭最后一个不再需要的任务标签后，浏览器正常回收窗口。

## AI 的关页规则

1. 开始前核对本聊天已有任务，同一项工作继续使用同一任务，优先在该窗口内打开必要标签。
2. 操作过程中及时关闭已经用完的自有搜索页、重复中间页和确认无用的登录跳转。
3. 回答结束前列出本任务页面，默认 finish keepTabIds:[]。已经读完或已在聊天提供引用链接，不构成继续开着网页的理由。
4. 只有用户明确要求保持打开、必须留在网页完成后续人工操作，或有未保存/不确定状态时才保留具体 ID。
5. 最小化、长时间未聚焦、标题相同或相同网址均不证明窗口无用或属于插件；其他活动会话和普通 Edge 窗口不参与自动清理。

旧版本留下但已失去可靠归属的窗口，不能在更新后仅凭标题批量关闭。该限制保护后来被用户接管的页面。本轮修复防止之后的结果保留继续增加窗口，并加强任务内的及时清理；不把未知旧窗口报告为已清理。

## 加载与诊断

等活动任务结束后备份更新扩展和 Harness 接收端，再加载两边。使用 DSH Launcher 时要核对它实际托管的后台，开关插件若仍显示旧版，需要正常重开实际服务。diagnose 的 inPlaceResults:true 才表明活动扩展具备本修复。

CLI 仍为 0.4.2，协议仍为 1.8，没有升级 Harness 内核或其他插件。窗口数量减少不等于固定比例的内存节省，未实测内存时不宣称节省倍率。
